# 17 · 会话两侧可拖动但无作用的条（疑似原版遗留）→ 定位并删除

| 项 | 内容 |
| --- | --- |
| 分类 | 干扰清理（疑似宿主遗留元素） |
| 优先级 | P1（不影响功能，但持续干扰操作与观感） |
| 截图 | 待补（请放入 `docs/issues/img/17-*.png`：能拍到那条的位置与光标形状最好） |
| 涉及代码 | 待定位：宿主 `ui-layout` / 会话容器的分栏手柄，或插件 `features/conversation/**` 里的覆盖层；可能落到 `src/client/features/conversation/conversation.css` 或 `src/client/theme/composer.css` |
| 关联锚点 | 先查 `src/client/compat/host-dom.ts` 是否已有登记；没有就新增登记（含 Windows 别名） |

## 问题

会话区域**左右两侧各出现一条可以拖动、但拖动后没有任何作用的条**（鼠标移上去会变成可拖动的光标，拖了不影响布局）。用户判断这**可能是原版（宿主）遗留**的元素。

## 目标

1. 找到这条东西到底是什么：宿主的分栏手柄 / gutter / 一个透明的 resize 覆盖层 / 插件的某个占位元素。
2. 若它**没有实际功能** → 删除或隐藏（隐藏后不得留下热区、光标变化或占位空白）。
3. 若它**其实有功能**（例如真的能调整某栏宽度） → 停止改动，在报告里给出证据并说明建议（保留 / 反馈给宿主），**不要擅自删掉有功能的东西**。

## 验收标准

1. 定位结论明确：给出该元素的真实 DOM 路径 + 类名/属性 + 由哪个包渲染（附 `app.asar` 内的文件与行号证据）。
2. 会话**左右两侧**都不再出现该条；鼠标移动到原位置**不再出现 resize/col-resize 光标**。
3. 隐藏后：会话内容宽度、滚动条、左右分栏布局、页面滚动均**与改动前一致**（用盒模型数值对照说明，不是"看起来没问题"）。
4. 不得误伤真正的滚动条、分栏手柄、拖拽排序的落点指示等有功能的元素。
5. 若涉及视图切换/动画（插件已有 `compat/view-switch.ts`、`conversation-fade.ts`），确认改动后动画与几何补偿仍然正确。
6. `npm run check` 通过。

## 落地提示

- 定位顺序建议：①在运行中的应用里用「审查元素」抓到它的类名/`data-*`/`cursor` 样式；②拿类名去已安装 `app.asar`（`dsh/node_modules/@deepseek-ai/dsh-client-ui-*/lib/client.js` 与内联 CSS）里反查渲染它的组件；③若是 web 前端产物（`dsh-web-frontend/dist/assets/*`），按既有做法追加到 `tokens.css` 里的静态资产说明段落，不要写死哈希。
- 常见的"可拖动但无作用"来源：`ui-layout` 的分栏 `handle` 在没有开启分栏时仍然渲染；或某容器上的 `resize: horizontal` / `cursor: col-resize` 残留；或网格 gutter 的背景元素。
- 结论若为「宿主元素、插件只能隐藏」：用最小作用域（锚定会话根 + 该元素特征）隐藏，并把选择器写进 `host-dom.ts` 登记表；注释里写清"为什么它无功能"的证据，避免后人误以为在掩盖宿主功能。
- 不要顺手重构无关样式；不要启动 GUI 抢占资源（必要时可由 Lead 安排一次性核对）。
