# 组件加载与响应核验（2026-10-26）

首轮只测了四个转录适配器，不能代表所有组件。此次对 34 个浏览器测试文件的 66 项场景补做性能采样，另测构建包初始化，并在正在运行的 DSH 上录制模型／Effort 菜单。覆盖的是下表列出的具体路径，仍不是所有数据规模、宿主接口和业务状态的穷举。

## 方法与读数边界

- Chrome 156.0.8078.48；浏览器夹具使用真实插件组件与 CSS，Host 数据／动作由演示端口提供。按文件串行运行，避免同时启动多个测试争抢 CPU。
- `page-performance.mjs` 只在 CCD_PERF_DIR 设置时启用。记录 Performance、Long Tasks、Event Timing 和 CPU profile；CCD_PERF_TRACE=1 另存时间线。
- 自定义命名读数从操作开始，等断言的 DOM 状态就绪，再等两次 requestAnimationFrame 回调。它是“状态就绪并经过绘制机会”的代理指标，包含约一至两帧等待，不是 INP，也不代表动画已全部结束。
- 既有测试中的普通 evaluate 只记录其期间累计脚本／布局工作；其中可能包含断言、主动等待和动画。不能把整项测试用时或 evaluate 的墙钟用时称为用户响应时间。
- Event Timing 仅收集浏览器报告、达到 16ms 采样阈值的事件。没有事件样本表示无可报告数据，不表示响应为 0。
- 独立夹具会打包 React 开发运行库；实际插件复用 DSH 的运行库。因此数值适合定位与同条件对照，不应与实机直接混用。

最终保留 80 份成功的页面 profile：77 份组件夹具、3 份构建包初始化。独立夹具录到 409 条 Event Timing，最大 56ms；最终夹具中未录到超过 50ms 的 longtask。这里只描述这些采样，不能推断所有业务路径都没有长任务。

## 找到并修复的慢点

500 个未知模型、开启模型图标时，首次打开约 96.6ms，出现 84ms longtask；CPU profile 的热点为 hasPhrase／matchText。每行都多次遍历全部图标别名，并重复匹配相同 provider。

改为按短语首词和完整 compact 字符串索引候选；保留原始的全局别名优先级及 routing 排除规则。显式长别名仍允许 compact 子串匹配，短别名继续要求词边界。最多 2048 条缓存同时记录命中与未命中，避免目录变化造成无限增长。

同条件复测首次打开为 47.4ms，对应累计脚本段从 80.5ms 降为 32.3ms，没有再次录到该长任务；最终定向录制为 45.3ms。与修改前代码对照 8,644 组输入结果一致，并增加了重命名、词边界、routing、优先级和缓存淘汰回归。

## 真实 DSH 录制

9222 未开放，但通过应用的 DevTools 快捷键成功打开 Performance。没有重启、重载、发送消息或改模型／Effort 设置；仅打开模型菜单、Escape 关闭、打开 Effort、Escape 关闭。DevTools 停靠使页面变窄，因此这不是正常窗口尺寸下的完整验收。录制后关闭 DevTools，原会话布局恢复。

- 录制长约 56.06s，其中大部分为空闲；765 个主线程任务。
- 模型菜单 click 的 Event Timing 为 58.079ms，处理阶段 11.948ms。
- Effort click 为 41.812ms，处理阶段 14.508ms。
- 两次 Escape 的 Event Timing 为 52.466ms、65.022ms。
- 开头 229.599ms 的长任务内，CpuProfiler::StartProfiling 占 226.972ms。保留这条原始记录，不把 profiler 启动开销归因于菜单。开始一秒后最大的主线程任务为 17.334ms。
- 截图与资源正文导出均关闭。时间线只保留本地；未将用户会话内容写入报告。
- 控制台另见 experimental-inspector 对本地 9230 的反复连接失败。这来自其他插件，作为背景负载记录，未修改该插件或据此推断它造成菜单延迟。

这段录制来自当时正在运行的客户端，未重新加载新安装包，不能用来证明新优化的实机前后收益。完整冷启动、全部真实接口和表中列出的未测部分仍需额外场景。

## 复现与产物

```sh
node scripts/summarize-page-performance.mjs artifacts/performance/components
npm run build
CCD_PERF_DIR=artifacts/performance/bundle CCD_PERF_TRACE=1 node scripts/profile-bundle-load.mjs
```

本次原始数据在 artifacts/performance/components-final/（逐页 JSON、CPU profile、时间线和 summary.md）、models-before/、models-after/；实机录制与摘要在 live-dsh/。artifacts 被 Git 忽略，不随包发布。普通测试不启用性能计时阈值，避免用机器抖动决定 CI 成败。

## 完整回归与打包

默认 pack:local 的并发浏览器检查出现三项超时；另一个计数断言遇到了迟到的动画移除。该计数测试改为 reduced-motion，隔离它要验证的流式工作量；动画行为仍由既有动画测试覆盖。随后将完整测试集按文件串行运行：661 项全部通过，无跳过或取消，类型、架构与构建检查也通过。包级 VM 替身补齐真实 DOM 的 hasAttribute 和定时器 API，并新增卸载后无残留 interval 的断言；check:package 重新通过。完成这些检查后打包时跳过重复 prepack，使用独立保留路径安装到 desktop profile。
